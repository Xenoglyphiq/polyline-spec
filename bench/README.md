# Benchmarks

| Path | What |
|---|---|
| `route_100k.polyline` | 100,000 points at precision 5, one line (the trailing newline is not part of the polyline). Generated by `generate.py` from a seeded random walk; re-running gives identical bytes. |
| `rust/` | The reference: the Rust `polyline` crate (pinned `=0.11.0`) timed with the method below. |

## Method

Every port measures exactly this, so ratios are comparable:

1. Read `route_100k.polyline` and strip the trailing newline. Precision 5, default limits.
2. Decode it once, untimed, to get the points. Check that encoding those points reproduces the input exactly.
3. **encode**: 3 warm-up runs, then 15 timed runs of `encode(points)`. Report the median, and the minimum.
4. **decode**: 3 warm-up runs, then 15 timed runs of `decode(text)`, including allocating the result. Report the median and minimum.
5. Use a monotonic clock, an optimized build (the port README names its build mode), and a quiet machine: no other heavy jobs running.

The ratio is **port median ÷ reference median**, per operation. The target is within 2× of the reference (`spec/SPEC.md` §8).

## Reference timings

Run from the repo root:

```
cargo run --release --manifest-path bench/rust/Cargo.toml
```

| Date | Machine | encode median | decode median |
|---|---|---|---|
| 2026-10-05 | Apple M5 Pro, macOS 26.6.2, on AC power | 0.891 ms | 0.612 ms |
| 2026-10-05 (second session, after the ports' optimization pass) | same | 0.892 ms | 0.643 ms |

Each number is the median of three medians: the reference and every port ran three rounds, interleaved, in one session (load average about 4.9 on 18 cores), so background noise hit all of them alike. Ports compare against the reference from the same session; re-measure the reference whenever ports are measured on a different machine.
